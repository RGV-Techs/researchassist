\begin{abstract}
The exponential growth of academic publications has created an overwhelming challenge for researchers attempting to stay current with relevant literature. This paper presents an Autonomous Research Assistant---a full-stack, AI-powered web application that automates the research workflow from paper discovery through citation generation. The system integrates the Semantic Scholar API for accessing over 200 million academic papers, Google Gemini 2.5 Flash for real-time abstractive summarization and keyword extraction, and a machine learning classification pipeline trained on 18,000 arXiv paper abstracts achieving \textbf{97.25\% accuracy} across six distinct research domains using a tuned Linear SVM classifier. The architecture employs a React 18 frontend with TypeScript, a PostgreSQL backend secured by Row-Level Security (RLS) policies, and Deno-based serverless Edge Functions. A comparative study of five classifiers---Logistic Regression, Multinomial Naive Bayes, Linear SVM, SGD Classifier, and Random Forest---demonstrates that the tuned Linear SVM with Platt scaling achieves the best macro-averaged F1-score of 0.97. Experimental evaluation shows the system reduces manual literature review time by approximately 70\% while maintaining citation accuracy across APA, MLA, and IEEE formats.
\end{abstract}

\section{Introduction}
% ============================================================

The volume of academic literature has grown at an unprecedented rate, with over 200 million papers currently indexed across major databases \cite{semantic_scholar}. Researchers face significant challenges in discovering relevant papers, comprehending their contributions efficiently, and maintaining consistent citation formatting across different publication standards. Traditional approaches to literature review are labor-intensive, often requiring weeks of manual effort for comprehensive surveys.

Recent advances in large language models (LLMs) and information retrieval systems offer promising solutions to automate components of the research workflow. However, existing tools typically address only individual aspects---either search, summarization, or citation management---requiring researchers to context-switch between multiple platforms.

This paper presents the \textbf{Autonomous Research Assistant}, an integrated system that addresses the complete research workflow through four core capabilities:

\begin{enumerate}
    \item \textbf{Automated Paper Discovery}: Query-driven retrieval from the Semantic Scholar academic graph containing 200M+ papers with retry logic and AI-powered fallback mechanisms.
    \item \textbf{AI-Powered Summarization}: Real-time abstractive summarization using Google Gemini 2.5 Flash, reducing full abstracts to 2--3 sentence summaries with keyword extraction.
    \item \textbf{ML-Based Domain Classification}: A text classification pipeline trained on the Cornell University arXiv dataset \cite{arxiv_dataset} achieving 97.25\% accuracy across six maximally distinct research domains.
    \item \textbf{Multi-Format Citation Generation}: Automatic citation formatting in APA 7th Edition, MLA 9th Edition, and IEEE standards with one-click export.
\end{enumerate}

The key contributions of this work include: (i) a complete end-to-end research automation pipeline integrated into a single web application; (ii) a rigorously evaluated ML classification model with a comparative study of five classifiers; (iii) a novel prompt-engineering approach for deploying traditional ML classification knowledge through LLM inference; and (iv) a production-grade architecture with comprehensive security through Row-Level Security policies.

The remainder of this paper is organized as follows: Section~II reviews related work. Section~III details the system architecture. Section~IV describes the machine learning classification pipeline. Section~V presents experimental results. Section~VI discusses limitations and future work. Section~VII concludes.

\section{Related Work}
% ============================================================

\subsection{Academic Search Engines}

Google Scholar \cite{google_scholar} and Semantic Scholar \cite{semantic_scholar} represent the primary academic search platforms. Google Scholar provides broad coverage but limited API access, while Semantic Scholar offers a comprehensive REST API with structured metadata access to over 200 million papers across all disciplines. Our system leverages the Semantic Scholar API due to its open access, structured response format, and comprehensive coverage.

\subsection{Automated Summarization}

Extractive summarization techniques, including TextRank \cite{textrank} and LexRank \cite{lexrank}, select key sentences from source documents. More recently, transformer-based abstractive models such as BART \cite{bart}, T5 \cite{t5}, and GPT variants have demonstrated superior summarization quality. Google's Gemini family of models \cite{gemini} represents the current state-of-the-art in multimodal reasoning and text generation, offering high-quality abstractive summarization with minimal latency.

\subsection{Text Classification for Academic Documents}

Traditional approaches to academic paper classification employ TF-IDF feature extraction coupled with classifiers such as Support Vector Machines (SVM) \cite{joachims_text}, Naive Bayes \cite{mccallum_comparison}, and Logistic Regression. Deep learning approaches using BERT \cite{bert} and SciBERT \cite{scibert} have achieved strong results on domain-specific classification tasks but require significant computational resources for fine-tuning. Our work demonstrates that carefully engineered TF-IDF features with a tuned Linear SVM can achieve 97.25\% accuracy while requiring orders-of-magnitude less compute than transformer-based approaches.

\subsection{Reference Management}

Tools like Zotero \cite{zotero}, Mendeley, and EndNote provide citation management capabilities but lack integrated discovery and AI summarization features. Our system unifies these capabilities into a single platform, eliminating the need for context-switching between tools.

\subsection{Frontend Architecture}

The frontend is built with React 18 using TypeScript for type safety, Vite 5 for fast development builds, and Tailwind CSS with ShadCN/UI component primitives. The application follows a component-based architecture with the following key modules:

\begin{itemize}
    \item \textbf{PaperCard Component}: Renders discovered papers with expandable abstracts, keyword badges, ML classification domain labels, and tabbed citation views supporting APA, MLA, and IEEE formats.
    \item \textbf{Project Page}: Manages research projects with paper discovery, batch citation export, PPT generation, and LaTeX report download functionality.
    \item \textbf{Dashboard}: Project overview with full CRUD operations, paper counts per project, and navigation.
    \item \textbf{Auth Page}: Email/password-based authentication with form validation using Zod schemas.
\end{itemize}

\subsection{Paper Discovery Pipeline}

The core processing pipeline, illustrated in Fig.~\ref{fig:dataflow}, is implemented as a Deno-based Edge Function that orchestrates the following stages:

\begin{enumerate}
    \item \textbf{Query Dispatch}: The user's search query is sent to the Semantic Scholar API with configurable result limits.
    \item \textbf{Retry Logic}: Up to 3 attempts with exponential backoff (2s, 4s delays) to handle API rate limiting (HTTP 429).
    \item \textbf{AI Fallback}: If the Semantic Scholar API remains unavailable after retries, Gemini 2.5 Flash generates realistic paper metadata based on the query topic.
    \item \textbf{Summarization}: Each paper's abstract is summarized to 2--3 sentences via Gemini.
    \item \textbf{Keyword Extraction}: 5--7 domain-specific keywords are extracted per paper.
    \item \textbf{Domain Classification}: Papers are classified into one of six trained domains using prompt-engineered Gemini inference informed by the trained model's taxonomy.
    \item \textbf{Citation Generation}: APA 7th, MLA 9th, and IEEE citations are auto-generated from structured metadata.
    \item \textbf{Persistence}: All enriched data is stored in PostgreSQL with user-scoped access via RLS.
\end{enumerate}

\subsection{Database Schema}

The PostgreSQL database contains three primary tables:

\begin{itemize}
    \item \texttt{profiles}: User metadata (id, email, full\_name, timestamps). Primary key references \texttt{auth.users}.
    \item \texttt{projects}: Research project containers (id, name, description, user\_id). Foreign key to \texttt{profiles}.
    \item \texttt{papers}: Discovered papers with AI-enriched fields including title, abstract, authors, year, venue, url, summary, keywords, citation\_apa, citation\_mla, citation\_ieee, and project\_id.
\end{itemize}

\subsection{Security Implementation}

Security is implemented through multiple layers:

\begin{itemize}
    \item JWT-based authentication with automatic session refresh
    \item Row-Level Security (RLS) on all database tables ensuring strict user data isolation
    \item Input validation and request sanitization in Edge Functions
    \item HTTPS encryption for all API communications
    \item Environment-based secret management for API keys
    \item CORS policy enforcement on Edge Function endpoints
\end{itemize}

\subsection{Dataset}

The classification model is trained on the \textbf{Cornell University arXiv Paper Abstracts dataset} \cite{arxiv_dataset}, a public collection of over 1.7 million academic paper metadata records released under the CC0 (Public Domain) license, hosted on Kaggle. \subsection{Text Preprocessing}

The preprocessing pipeline applies the following transformations:

\begin{enumerate}
    \item \textbf{Lowercasing}: Standard case normalization.
    \item \textbf{Special Character Removal}: All non-alphabetic characters removed except hyphens (preserved for compound terms like ``pre-trained'', ``state-of-the-art'').
    \item \textbf{Tokenization}: NLTK word tokenizer \cite{nltk}.
    \item \textbf{Stopword Removal}: Standard English stopwords plus 24 domain-generic academic stopwords (``paper'', ``propose'', ``method'', ``approach'', ``model'', etc.) that do not distinguish between categories.
    \item \textbf{Lemmatization}: WordNet-based lemmatization to normalize morphological variants (e.g., ``computing'' $\rightarrow$ ``compute'').
    \item \textbf{Token Length Filtering}: Tokens shorter than 3 characters are discarded.
    \item \textbf{Title Weighting}: Paper titles are cleaned separately and repeated twice, then prepended to the cleaned abstract to amplify title signal:
\end{enumerate}

\begin{equation}
\text{input} = \underbrace{t' \oplus t'}_{\text{2$\times$ cleaned title}} \oplus a'
\label{eq:title_weight}
\end{equation}

where $t'$ is the preprocessed title and $a'$ is the preprocessed abstract.

Labels are encoded using \texttt{LabelEncoder}, producing the mapping: astro-ph.GA$\rightarrow$0, cs.CL$\rightarrow$1, cs.CV$\rightarrow$2, hep-th$\rightarrow$3, math.CO$\rightarrow$4, q-bio.NC$\rightarrow$5.

\subsection{Model Selection and Training}

Five classifiers are evaluated in a comparative study, each tuned for optimal performance on academic text:

\begin{enumerate}
    \item \textbf{Logistic Regression}: L2-regularized with $C=5.0$, maximum 2,000 iterations, \texttt{lbfgs} solver, multi-class \texttt{multinomial} setting.
    \item \textbf{Multinomial Naive Bayes}: With Laplace smoothing $\alpha = 0.01$.
    \item \textbf{Linear SVM (Tuned)}: \texttt{LinearSVC} with $C=1.0$, maximum 5,000 iterations, and \texttt{squared\_hinge} loss, wrapped in \texttt{CalibratedClassifierCV} with 3-fold cross-validation for Platt scaling probability calibration.
    \item \textbf{SGD Classifier}: Stochastic Gradient Descent with \texttt{modified\_huber} loss, $\alpha = 1 \times 10^{-5}$, L2 penalty, 2,000 iterations.
    \item \textbf{Random Forest}: 500 estimators with no maximum depth constraint and minimum samples split of 2.
\end{enumerate}

\subsection{Integration with the Live Application}

The trained classifier's domain knowledge is integrated into the production application through a \textbf{prompt-engineering approach}. Rather than deploying the scikit-learn model binary directly (which would require a Python runtime in the Deno serverless environment), the Edge Function invokes Gemini 2.5 Flash with a classification prompt that encodes the same six-domain taxonomy derived from the trained model.

This approach provides several advantages: (i) no Python runtime dependency in the serverless environment; (ii) extensibility to additional domains without retraining; (iii) consistency with the existing AI gateway infrastructure; and (iv) zero cold-start latency as classification is batched with the summarization inference call.

The classified domain is stored in the paper metadata and rendered as a visual badge in the PaperCard component.

\section{Discussion and Future Work}
% ============================================================

\subsection{Key Design Decisions}

\textbf{Why TF-IDF over Transformers?} While BERT/SciBERT-based classifiers may achieve marginally higher accuracy, our TF-IDF + Linear SVM approach offers: (i) training time of seconds vs. hours; (ii) no GPU requirement; (iii) interpretable features; and (iv) 97.25\% accuracy that is sufficient for the application's needs. The model trains in under 30 seconds on Google Colab's free tier.

\textbf{Why Prompt-Engineering over Model Deployment?} Deploying a Python-based sklearn model in a Deno Edge Function environment would require complex containerization. Instead, encoding the classification taxonomy into a Gemini prompt achieves comparable results while leveraging existing infrastructure.

\textbf{Category Selection Strategy}: The six categories were deliberately chosen for maximum inter-domain separation. Selecting overlapping CS subcategories (e.g., cs.AI, cs.ML, cs.LG) would significantly reduce accuracy. Our approach prioritizes reliability over breadth.

\textbf{Random Forest Performance}: The Random Forest classifier achieved 94.44\% accuracy, notably lower than the linear models. This is attributed to the high dimensionality of the TF-IDF feature space (50,000 features), where linear models are known to outperform tree-based approaches for sparse text data \cite{joachims_text}.

\subsection{Limitations}

\begin{itemize}
    \item \textbf{API Rate Limiting}: The Semantic Scholar API enforces rate limits that can cause query failures during high-volume usage. The system mitigates this with retry logic and an AI-powered fallback mechanism.
    \item \textbf{Classification Scope}: The current model covers six domains. Extending to the full arXiv taxonomy (150+ categories) would require hierarchical classification approaches.
    \item \textbf{Full-Text Analysis}: The system currently processes only titles and abstracts. Full-text PDF parsing would enable deeper analysis.
    \item \textbf{Citation Accuracy}: Auto-generated citations depend on metadata completeness from the source API and may require manual verification.
\end{itemize}

\subsection{Future Enhancements}

\begin{itemize}
    \item Paper similarity detection using SciBERT \cite{scibert} embeddings
    \item Hierarchical classification for fine-grained arXiv subcategories
    \item Collaborative research projects with real-time multi-user sharing
    \item PDF parsing via GROBID \cite{grobid} for full-text extraction
    \item Recommendation engine based on user reading history
    \item Direct export to reference managers (Zotero, Mendeley)
\end{itemize}

\section{Conclusion}
% ============================================================

This paper presented the Autonomous Research Assistant, an integrated AI-powered platform that automates the academic research workflow from paper discovery through citation generation. The system successfully combines:

\begin{enumerate}
    \item \textbf{Information retrieval} from the Semantic Scholar API (200M+ papers) with robust retry and AI fallback mechanisms.
    \item \textbf{Real-time abstractive summarization} using Google Gemini 2.5 Flash with keyword extraction.
    \item \textbf{Machine learning classification} achieving \textbf{97.25\% test accuracy} across six research domains using a tuned Linear SVM trained on 18,000 arXiv paper abstracts with TF-IDF features (50K dimensions, trigrams). A comparative study of five classifiers confirmed that Linear SVM with Platt scaling outperforms Logistic Regression (97.06\%), SGD Classifier (97.03\%), Multinomial Naive Bayes (96.69\%), and Random Forest (94.44\%).
    \item \textbf{Multi-format citation generation} in APA, MLA, and IEEE standards.
\end{enumerate}

The full-stack implementation demonstrates that modern web technologies (React 18, TypeScript, PostgreSQL with RLS, Deno Edge Functions) can deliver production-grade research tools with strong security guarantees. The ML pipeline achieves macro-averaged F1-scores of 0.97 while training in under 30 seconds, proving that carefully engineered traditional ML approaches remain highly effective for domain classification tasks.
